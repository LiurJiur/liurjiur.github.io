# 《CAT HELP：玩具球失踪事件》游戏设计概要

## 1. 文档信息

- 项目代号：`cat-help`
- 暂定名称：《CAT HELP：玩具球失踪事件》
- 游戏类型：文字检索、非线性调查、轻推理
- 目标平台：桌面端与移动端现代浏览器
- 目标时长：首次通关 45～60 分钟
- 目标版本：可独立游玩的单案件 MVP

## 2. 一句话概念

玩家受猫妈妈桂花委托，进入猫宅智能终端 `CAT HELP`，通过检索家庭聊天、智能设备日志和猫猫证词，还原一颗红色铃铛球在晚饭后离奇消失的全过程。

## 3. 设计目标

游戏希望提供类似档案检索式推理游戏的发现感，但采用温暖、轻松且没有真正反派的家庭故事。

核心体验由四部分组成：

1. **主动发现**：玩家通过名字、地点、时间和物品等关键词主动寻找记录。
2. **交叉验证**：单条记录只提供局部事实，关键结论需要两条以上线索互相印证。
3. **可爱误会**：多只猫隐瞒了一点小事，另一些猫则记错或漏看了细节，却没有谁故意偷走玩具球。
4. **完整复盘**：通关时，玩家不仅找到球，还能解释球为何沿着这条路线失踪。

## 4. 目标玩家

- 喜欢《Type Help》《Her Story》《疑案追声》等信息检索或叙事推理游戏的玩家。
- 喜欢猫猫、轻喜剧和无伤亡悬疑故事的休闲玩家。
- 能接受大量阅读，但不一定熟悉传统文字冒险命令的玩家。

游戏不要求玩家具备编程或命令行知识。终端只是叙事包装，所有重要操作都应同时支持键盘输入和点击。

## 5. 故事设定

### 5.1 背景

故事发生在一栋由猫猫家族居住的两层小屋“桂花宅”。家中安装了智能家庭系统 `CAT HELP`，会保存家庭群聊、智能项圈位置、房间传感器事件、喂食器记录和扫地机器人日志。

晚饭后，黑猫小酒发现自己最喜欢的红色铃铛球不见了。猫妈妈桂花在终端中创建“失物调查”，玩家以临时调查员身份获得当晚有限的家庭记录权限。

### 5.2 故事基调

- 悬疑来自信息缺失和证词矛盾，而不是危险或恶意。
- 每一次“可疑行为”最终都应落到符合角色性格的小秘密上。
- 笑点来自猫的习性与智能设备对猫行为的机械化描述。
- 结局强调家人共同造成的小意外，以及一起解决问题的满足感。

### 5.3 核心谜题

玩家最终需要回答：

1. 谁是最后一个正常玩球的猫？
2. 球为何离开客厅？
3. 小酒之后，谁第一次主动拿走了球？
4. 哪两只猫为掩盖自己的秘密，提供了与客观记录冲突的证词？
5. 球后来被什么东西带走？
6. 球现在在哪里？

## 6. 主要角色

| 角色 | 身份与性格 | 表面嫌疑 | 实际秘密 |
| --- | --- | --- | --- |
| 桂花 | 三花猫妈妈，细致、有组织能力 | 熟悉家里所有收纳位置 | 调查发起者，没有隐瞒关键行动 |
| 小酒 | 黑猫弟弟，通体乌黑、眼睛圆亮；玩心重、说话直接 | 最后一个公开承认玩球 | 玩球时误撞了厨房零食罐，怕挨批评而省略此事 |
| 铁胆 | 银渐层表哥，银白被毛、背部有灰黑毛尖；贪吃、嘴硬，名字威风但遇事心虚 | 项圈记录与证词不一致 | 偷吃掉落的小鱼干，并把零食罐推回原位 |
| 小流儿 | 白猫姐姐，通体雪白、尾巴修长；安静、喜欢收藏，行动轻巧 | 被看到抱着一个蓝纸箱 | 把球当成“宝物”暂时放进秘密收藏箱，准备稍后归还 |
| 糖心 | 金渐层表妹，金色短毛、琥珀色眼睛；活泼好动、脾气暴躁、护短 | 案发前在客厅和走廊来回追逐，容易被怀疑碰过球 | 追逐逗猫棒时撞歪厨房门，却没有接触玩具球；因怕被说莽撞而起初不愿提起 |
| 松花 | 长毛狸花表弟，毛发蓬松、胸腹颜色较浅；怕冷、爱睡觉、醒来慢吞吞 | 声称一直睡觉，证词听起来与铁胆相似 | 确实在暖气垫上睡觉；翻身时看见小扫经过，是机器人路线的旁证 |
| 胡椒爷爷 | 灰猫长辈，爱打盹、观察细致 | 证词中的颜色和时间不可靠 | 把小流儿与纸箱的颜色记反，但听见了关键的两次声响 |
| 小扫 | 扫地机器人，矮圆机身、顶部有一圈绿色状态灯，按程序行动 | 运行路径经过所有关键地点 | 撞开纸箱后，球落入其后部拖布收纳篮并被带回充电座 |

## 7. 地点

| 地点 | 叙事作用 |
| --- | --- |
| 客厅 | 球最后一次被公开看见的地方，也是调查起点 |
| 厨房 | 球撞到零食罐，产生第一组证词矛盾 |
| 走廊 | 小流儿藏匿纸箱、小扫撞箱的关键地点，也是松花暖气垫所在位置 |
| 楼梯口 | 胡椒爷爷打盹并听见两次不同声响的位置 |
| 洗衣阳台 | 小扫的充电座所在地，也是球的最终位置 |
| 储物间 | 蓝纸箱的来源，用于确认小流儿拿走了哪个箱子 |

## 8. 核心玩法循环

```text
阅读初始委托和现有记录
        ↓
发现名字、地点、物品或时间关键词
        ↓
搜索关键词或点击高亮词
        ↓
解锁新记录、档案或设备日志
        ↓
标记事实并更新已知时间线
        ↓
发现矛盾，继续交叉检索
        ↓
提交阶段推理或最终答案
```

玩家可以用不同顺序调查各条支线，但关键线索必须可由初始资料逐步到达，不能依赖无提示猜词。

## 9. 终端功能

### 9.1 MVP 命令

| 命令 | 功能 | 示例 |
| --- | --- | --- |
| `help` | 显示命令说明和当前建议 | `help` |
| `inbox` | 查看委托与系统消息 | `inbox` |
| `list` | 列出已解锁记录 | `list` |
| `open` | 打开指定记录 | `open CHAT-01` |
| `search` | 搜索角色、地点、时间或物品 | `search 厨房` |
| `profile` | 查看已解锁角色档案 | `profile 铁胆` |
| `map` | 查看房间关系和已知事件 | `map` |
| `timeline` | 查看玩家已确认的时间线 | `timeline` |
| `notes` | 查看发现过的关键词与事实 | `notes` |
| `hint` | 获取渐进式提示 | `hint` |
| `solve` | 进入最终推理界面 | `solve` |

### 9.2 易用性要求

- 支持点击文件名、人物名和关键词。
- 支持上下键浏览输入历史。
- 支持命令与关键词自动补全。
- 支持简繁体、常用昵称和同义词映射。
- 未找到结果时提供相近词，而不是只显示“错误”。
- 新解锁记录、未读记录和含未解决矛盾的记录使用不同标记。
- 玩家不需要记住记录编号即可完成游戏。

## 10. 调查系统

### 10.1 记录解锁

记录有三种解锁方式：

- 初始可见：调查开始时直接提供。
- 关键词解锁：搜索已在其他记录中出现的有效关键词。
- 组合解锁：需要先发现两个概念，例如“扫地机器人 + 走廊”。

组合解锁只检查玩家是否已经发现概念，不要求输入固定格式。

### 10.2 笔记与事实

系统自动记录玩家已经发现的：

- 角色
- 地点
- 物品
- 时间点
- 已确认事实
- 尚未解释的矛盾

玩家可以将记录中的句子标记为重要，但 MVP 不要求实现自由文本笔记。

### 10.3 推理提交

`solve` 使用选择加排序的方式，避免最终答案依赖精确文字输入：

- 从已知角色、物品和地点中选择答案。
- 将五张事件卡按时间排序。
- 对每个结论选择至少一条支持证据。
- 错误答案只指出矛盾所在，不直接公布正确答案。

## 11. 提示系统

提示分为三级，按当前调查进度动态提供：

1. **方向提示**：指出值得重新查看的记录或矛盾。
2. **关键词提示**：给出下一步应搜索的概念类别或关键词。
3. **操作提示**：直接告诉玩家应打开或搜索的内容。

使用提示不会影响结局。结算页可以显示使用次数，但不进行负面评价。

## 12. 内容规模

MVP 计划包含：

- 8 个角色档案
- 6 个地点档案
- 约 42 条调查记录（含系统、档案、证词、日志、阶段结论与结局）
- 约 20 个规范关键词及其别名
- 5 个核心事实节点
- 4 组误导与补充支线
- 1 个最终推理
- 1 个主结局和少量结算文本变化

## 13. 美术与声音方向

### 13.1 视觉

- 主界面模拟温暖的家庭终端，而不是冷峻的黑客终端。
- 主色采用奶油白、暖金、墨黑、银灰和低饱和绿色，与主要角色毛色形成呼应。
- 文件图标可以使用爪印、铃铛、纸箱、鱼干和机器人等简单符号。
- 角色以小头像或剪影呈现，MVP 不依赖复杂动画。
- 关键发现允许出现短暂的爪印盖章或铃铛晃动反馈。

### 13.2 声音

- 输入、打开文件和解锁记录使用轻柔短音效。
- 部分“录音转写”可配猫叫、铃铛或碰撞声，但必须提供完整文字信息。
- 背景音乐保持低存在感，支持分别关闭音乐和音效。

## 14. 无障碍要求

- 所有音频线索必须有文字等价内容。
- 不仅依靠颜色区分记录状态。
- 支持键盘完成全部核心流程。
- 支持字号调整和减少动画。
- 保证文本与背景有足够对比度。
- 不设置要求快速反应或限时输入的谜题。

## 15. 技术与内容架构建议

游戏优先做成无需后端的静态 Web 应用，进度保存在浏览器本地。剧情内容应与界面代码分离，以结构化数据维护：

```text
src/
├── content/      角色、地点、记录、关键词和答案
├── engine/       搜索、解锁、推理校验和提示逻辑
├── state/        进度、存档和迁移
└── ui/           终端、档案、时间线和结算界面
```

每条记录至少包含：稳定 ID、标题、类型、正文、涉及概念、解锁条件和排序信息。存档应记录内容数据版本，以便未来升级时迁移。

## 16. MVP 不包含

- 多案件或章节选择
- 多人联机
- 生成式 AI 对话
- 自由输入的自然语言判题
- 配音和复杂角色动画
- 云端账户及跨设备同步
- 影响主线走向的多结局分支

这些功能只有在单案件的调查体验经过试玩验证后再考虑。

## 17. 完成标准

MVP 达到以下条件即可视为可发布试玩版：

- 新玩家无需外部说明即可理解基本操作。
- 所有必要记录至少有一条明确、可发现的解锁路径。
- 玩家能够仅凭游戏内证据推出全部最终答案。
- 任意合理调查顺序都不会造成永久卡关。
- 刷新页面后进度可以恢复，并可以主动清除存档重新开始。
- 桌面和移动端均可完成核心流程。
- 至少完成 5 次无提示盲测，其中多数玩家能在 60 分钟内完成。
